# WP11: Settings + catalogue screens (round 2)

Spec: [ui-fix-plan.md](../../design/ui-fix-plan.md) 5.14 to 5.17, section 6 copy rows, section 7 WP11; CLAUDE.md "No native browser UI"; WP4 map of QA native sites ([wp4-primitives-b.md](wp4-primitives-b.md)); R8 Product archive backend ([r8-product-archive.md](r8-product-archive.md)); QA findings (Settings, Products notes).
Owns `web/src/features/{settings,ingredients,products,shops,notifications,signin}/**`. No backend change. Shared file edit allowed: append these folders to every `fail_paths` line in `scripts/check-ui.rules`.
Acceptance: Settings index plus sub-pages; zero native controls in the six folders; Member colour on Avatars; Product archive UI; QA UX fixes.

## Decisions
- **Settings = index + sub-pages.** `/settings` is `SettingsIndexPage` (no forms): `PageHeader` "Settings", then three `ListGroup`s of icon `ListRow`s (`settingsGroups(isAdmin)`): *Household* (Household, Members, Meal Slots, Planning rules, Shops), *You* (Your preferences, Notifications), *Admin* (Allowlist; Admins only, group dropped otherwise). New routes `/settings/{household,members,meal-slots,allowlist,preferences}`; `/settings/shops`, `/settings/notifications` and `/settings/planning` stay with their features. Every sub-page: `PageHeader` h1 + a "Back to Settings" link (href `/settings`). `SettingsPage`, `MealSlotList`, the `ShopsSettingsLink`/`NotificationSettingsLink` tiles and `useSettingsPage` go: split the hook per page. No separate "Barcodes" row: Shop Barcodes and Weight Barcode Rules live under their Shop (plan 5.14 lists "Barcodes"; it would duplicate the Shops target).
- **Member colour on Avatars.** `MemberAvatar` (settings/components) wraps `ui/Avatar` in `<span data-member-colour style="--member-colour">`; feature CSS draws a 2 px ring and tinted fill from the custom property, tokens elsewhere. Used by Members rows and Meal Slot Attendance. The `.settings__dot` is deleted. Member colour is picked with `ColorSwatches allowCustom` over `MEMBER_COLOURS` (8 named swatches, default Blue).
- **Rows.** Members: `ListRow` leading `MemberAvatar`, title name, meta linked User, trailing "×1.25" (copy fix; the label "Portion Factor" is in the editor); whole row opens the editor for an Admin, static for a plain User (row accessible name = the Member's name, since `ListRow` labels its target with the title).
- **Meal Slots = week view.** `MealSlotWeek`: 7 `role=group` rows Monday first (empty: "No Meal Slot"), slot chips "Dinner 19:30" (24 h, slot icon), per-weekday "Add Meal Slot on Friday" IconButton for Admins. Tapping a chip: Admin opens the `MealSlotEditor` (which has "Change a date"), a plain User goes straight to `DateAttendancePanel`. The 11 repeated "Edit / Change a date" text buttons are gone.
- **Meal Slots for several weekdays (QA).** Add mode shows a `MultiSelect` "Weekdays" (preselected from the add button's weekday); edit mode a single `Select` "Weekday". `onSave` always receives `MealSlotInput[]` (`slotInputsForWeekdays`: ascending, de-duplicated, own Attendance copy). `createSlotsSequentially` stops at the first failure; the page keeps the sheet open and the alert reads "Saved 1 of 3 Meal Slots. Tuesday failed: <server message>".
- **Linked User (QA).** `availableUsers(users, members, editing)` drops Users linked to another Member; the editor's own link stays. `MemberEditor` takes `members`.
- **Planning Horizon 1 to 28 (QA).** `NumberField min=1 max=28 step=1`; typed out-of-range values clamp on commit (primitive behaviour), `validateSettings` stays as the backstop. Cool-down 0 to 365, Leftover Use-by 1 to 14 get the same bounds. Quiet hours: two `TimeField`s. Planner Style: `Slider min 0 max 1 step 0.25` with the three anchor stops, plus the anchor chips and a caption ("Between Variety and Favourites") because off-stop values read as numbers in the Slider (PRIMITIVE REQUEST). Unit system and scheme: `Segmented`; accent: `ColorSwatches allowCustom` with a live preview tile (`data-testid=accent-preview`, `data-accent`). The "Remove" two-step in the Allowlist is a danger `ConfirmDialog` ("Remove cook@x?", confirm "Remove").
- **Human barcodes (QA).** `products/lib/barcodeFormat.ts`: `barcodeKind`, `formatBarcode` (EAN-13 `8 001505 005707`, UPC-A `0 36000 29145 2`, EAN-8 `9638 5074`, GTIN-14 `1 · 8 001505 005704`; opaque codes unchanged). Used for display and accessible names only; API calls keep the stored 14-digit code.
- **Weighed Shop Barcode labels (QA "rule 1" vs "rule 21").** The Product page printed the rule *id*, the Shop page the *prefix*. One function `weighedBarcodeLabel(prefix, item)` -> "Weighed · prefix 21 · item 00123" (no prefix when the rule is gone; an id is never shown). `ruleSummary` reads "prefix 21 · item digits 3-7 · value digits 8-12 · ...". `useProduct` loads the rules of the Shops that have weighed codes (`shopsApi.rules`). The rule Select of `AddShopBarcodeSheet` lists "A plain barcode", "Prefix 21", "Prefix 02" (meta: the rule summary).
- **Product archive UI (R8).** `productActions`, `deleteOutcome`, `applyArchivedFilter` (products/lib/archive.ts). Product page: "Archive Product" (active) / "Unarchive Product" (archived) plus "Delete Product", all `Button`s in a tile; Archive asks `useConfirm`: "Archive Passata 700 g?" body "It is left out of lists and Scans; its history stays. You can unarchive it." confirm "Archive"; Unarchive acts at once (no dialog), toast "<name> archived" / "<name> unarchived". Archived Product: "Archived" `Chip` beside the title and a line "Archived: retired, history kept."; nothing else is disabled. Delete: danger confirm "Delete <name>?" "This cannot be undone." confirm "Delete" (focus on Cancel); on `409 product_bought` a second dialog "<name> has been bought" / "A bought Product cannot be deleted. Archive it to retire it; its history stays." confirm "Archive", cancel "Keep"; other errors use the alert/toast. `productsApi.archive/unarchive`, `ProductFilter.includeArchived` (appended last: `?q=pas&includeArchived=1`), `useProduct.archive/unarchive` (invalidate `['products']` and `['catalog']`). List: `SearchField` + filter `Chip` "Archived" (`aria-pressed`); on = request `includeArchived=1` and show archived only; off = default list. Rows `ListRow` (name, meta "Ingredient · pack size", chevron), archived rows get a trailing "Archived" `Chip`; empty states "No Products yet" / "No archived Products". Pickers never request archived. The unknown-barcode "Unarchive <name>?" flow belongs to the scan team (R8 UI notes).
- **Ingredients.** `SearchField`, `ListRow`s `Garlic` / meta "g · keeps 30 days" (`displayName`, `ingredientMeta`); `MergeConflictList` choices are `RadioCards`; detail pages are section tiles with the field primitives.
- **Sign-in (5.16).** Feeder mark (`role=img` "Feeder") above the title; Google button is a white outlined link (`data-variant="google"`) with an inline SVG "G" (`data-google-g`, `aria-hidden`); card centred, `max-width: 400px`. The "G" carries Google's brand colours: add one allow-list entry for that file to the `colour-literals` guard (shared file).
- **Secondary colour (R6).** No remnants: the guard test asserts no `secondary` identifier or token in the six folders and that `Preferences` has only `scheme, accent, units`. (The `--color-secondary` aliases in `styles.css` are outside this team's scope.)
- **Native control replacements** (all per the WP4 map): `select` -> `Select`/`MultiSelect`/`ShopSelect`; date -> `DateField`; time -> `TimeField`; number -> `NumberField`/`Stepper`; colour -> `ColorSwatches`; range -> `Slider`; checkbox -> `Checkbox` (`AttendanceEditor`, `AllowlistPanel`, `DateAttendancePanel`); `NotificationSettingsView` -> `Switch`; radio -> `Segmented`/`RadioCards` (`RadioGroup.tsx` deleted if unused); `type=search` -> `SearchField`; Close/"×" buttons -> `IconButton`. Toasts for transient feedback, inline `role=alert` for form errors.
