## Decisions
- **Today layout** (`lib/compose.ts`): `TileSpec` is `{ id }` only (order and presence); each tile component fixes its own `Tile` variant and span. Order = 5.1 hierarchy: `nextMeal` (hero, full) , `toConfirm` (full), `advanceSteps` (1), `leftovers` (1, status leftover), `useSoon` (1, status spoil), `streak` (1, soft, from 1 day), `spoiled` (full, status danger, Stock's tile), `couldntPlan` (full, status danger). `TodayView` wraps each in `<div data-tile="<id>" class="today__slot">` (display: contents), shows `PageHeader` title "Today" + `dateLabel` ("Tue 10 Nov", `lib/heading.ts`). `useToday` returns `today`; the seam `useTodayPlan` returns `today`; `useTodayTileData` returns `now` and uses `heroMeal` (not `nextMeal`) for `nextSlot`.
- **Hero** = `plan/components/TonightHero` (replaces `NextMealTile`, exported from `plan/index.ts`): `Tile variant="hero" span="full"`, overline `DINNER · 19:30` (`lib/hero.heroOverline`, slot icon), "start 18:45" when `meal.startBy`, Recipe name h2, <= 2 why chips (`lib/chips.heroChips`), photo `RecipeThumb` 72 when `meal.photoUrl`, one primary `Cook · 45 min` (`heroCookLabel`) -> Cook Mode (`cookPath`). After the slot time (`heroPhase` = awaiting, until 2 h later when To confirm takes over, `days.heroMeal`) it reads "<Recipe> cooked?" with primary **Yes, Cooked** and secondary **Adjust**.
- **Yes, Cooked in one tap** (`hooks/useCookFlow.quickCook`): GET `.../cook`, POST `.../cooked` with `proposedLeftover` (no body for a meal served from a Leftover), invalidate plan, success toast `Cooked, nice one! 2 portions → Wed Lunch` (`lib/cook.cookedSuccessText`; the "success tile" of 2.2 is a toast, because the meal leaves the hero as soon as it is Cooked). Shortfall warnings of that path show as `ShortfallNotice`s. **Adjust** opens the Mark as Cooked sheet *on Today itself* (no detour through /plan): `useCookFlow` (`open/close/cook/stock/confirm/skip/quickCook/warnings`) + `CookFlowSheets` are shared by Plan and Today.
- **To confirm / Leftovers / Couldn't plan** (plan/components/TodayTiles): To confirm rows get **Yes, Cooked** (secondary), **Adjust** (secondary), **Not cooked** (tertiary); Leftovers is a half status-leftover tile (overline LEFTOVERS, rows "Soup" + meta "2 portions · Use by Thu") whose whole tile (stretched target "Leftovers to use") opens the Plan; Couldn't plan is a status-danger full tile.
- **Other Today tiles**: Advance Steps = half surface tile, `Alarm` icon, due time big; Use soon = half status-spoil, rows "Spinach · Thu" (`UseSoonItem.when` is now the short wording "today" / "tomorrow" / "Thu"), max 3 + "+2 more" (`lib/useSoon.splitUseSoon`); streak = soft half tile with `TileMetric` "3 wk" / "zero-waste streak" (`lib/streak.streakMetric`: whole weeks from 7 days, else "5 d").
- **Plan**: `PageHeader` "Plan", subtitle `dateRange` ("9 – 15 Nov"), action secondary sm **Regenerate** with the regenerate icon. Grid = own `PlanGrid` (`.plan-grid[data-columns]`, `usePlanColumns` -> 2 / 4 (>= 768) / 7 (>= 1200), no `matchMedia` = 7) because `BentoGrid` stops at 4 (PRIMITIVE REQUEST). Day tile (`DayTile`): `Tile variant="surface"`, `span` 2 for today (`data-today="true"` -> 2 px accent ring in CSS, no other fill), overline `WED 11` (`days.overline`), h2 `days.title` (Today / Tomorrow / Yesterday / long weekday; `label` kept for compatibility).
- **Planned Meal block** (`MealTile`, compact): slot icon + name, `IconButton` Swap (compact) for planned meals, `IconButton` Cook only for today's planned meal (B2, `lib/resolve.mayCook`), Recipe name as a button that opens the sheet (2-line clamp), **at most one chip** (`lib/chips.dayChip`: Cooked > Not cooked > Pinned > Leftover from <day> > first why; `best_available` never; a `leftover` why is dropped when the meal is served from a Leftover). Cooked / Not cooked blocks get `data-state` and 55 % opacity. Unfilled slot: dashed block (`data-unfilled`), danger status chip "Couldn't plan", reason text, tertiary **Choose a Recipe**. No Confirm/Pin/Mark as Cooked on the tile.
- **Chips in 2-column tiles** keep their background because every chip uses the new kinds (`why`, `state`, `status`, `count`), never `tone`; `plan.css` must not restyle `.chip` (CSS contract test).
- **Planned Meal sheet** (`PlannedMealSheet`, opened from a tile): title Recipe, meta "Dinner · 19:00", facts "1 Batch · 3.5 portions", Attendance `Avatar`s (optional `slot.attendance`), <= 3 chips + `count` chip "+N" (`chips.sheetChips`), actions in order **Cook** (primary, today, planned) · **Mark as Cooked** (today and past, planned) · **Swap** · **Pin / Unpin** (planned) · **Choose a Recipe**. Cooked / Not cooked meals have no actions. Acting closes the sheet first (one dialog at a time).
- **Pin** replaces Confirm in copy and API wrapper (`usePlanActions.pin`; the server route stays `.../confirm`).
- **Swap**: title "Swap for…", no subtitle, `ListGroup "Alternatives"` of <= 3 `ListRow`s (48 `RecipeThumb`, Recipe name, meta = first reason and "+0.5 portion Leftover"), tapping a row swaps and pins, toast "Swapped" + **Undo** (puts the previous Recipe back via PUT and, if it was not Pinned, `unpin`), tertiary **Keep it** closes. The reason is meta text, not a chip, because `ListRow` has no chip slot (PRIMITIVE REQUEST, optional).
- **Mark as Cooked sheet**: same props as today. Footer: primary full-width **Mark as Cooked**, secondary **No Leftover** (sets 0; only while the Leftover is > 0), tertiary **Not cooked**; "Use by Thu" as status chip meta (short weekday). Stock correction field is a `NumberField` (min 0, accepts "2,5"); `useTotalField` holds a number | null.
- **Choose a Recipe sheet**: `SearchField "Search Recipes"` + `ListGroup "Recipes"` of rows with `RecipeThumb` (`RecipeChoice` now carries `tags`, `imageUrl`, `totalMinutes`).
- **Regenerate confirm** (2.4): `useConfirm().confirm` with `lib/regenerate.regenerateConfirmCopy(n)`; n = `regenerateImpact(slots, today)` = planned, unpinned meals dated today or later. Cancel does nothing; the POST happens only after confirm. Zero says "No Planned Meals will change. Empty Meal Slots may be filled."
- **Planning rules** (`RulesEditors`): Meal Slot = `MealSlotSelect`; "Rule is for" = `Segmented` (a Recipe / a Tag); Recipe = `RecipeSelect`; **Tag = `Select` fed by the existing Tags** (both the Slot Rule and the Variety Rule) from `useTagChoices` -> `planApi.tags()` = GET `/api/tags` (read-only use of the recipes API, `TagChoice {name, recipes}`, options by `lib/rules.toTagOptions`, meta "3 Recipes"); weekly limit = `NumberField` (1 to 21, `null` = no cap; `VarietyDraft.maxPerWeek` is now `number | null`); not-consecutive = `Checkbox`. New copy: "Choose a Tag." replaces "Enter a Tag."; with no Tags: "Add Tags to your Recipes to use them here."
- **Copy (section 6)**: phrases `uses spinach before Thu`, `uses Stock: chicken thighs` (fallback `uses what is in Stock`), `Leftover from Tue`, `Leftover for Wed`, `Leftovers to come`, `best_available` -> '' ; `extraPortions` -> "+0.5 portion Leftover"; "Next Planned Meal" is gone (overline = slot); "Swap this Planned Meal" gone; streak sentence gone. Strings live in `plan/strings.ts` / `today/strings.ts` only.
- **Types** (optional until the API sends them): `PlannedMeal.cookMinutes/startBy/photoUrl/tags`, `PlanSlot.attendance`, `Alternative.photoUrl`. The UI renders without them.
- **CSS** (tokens only, delete unused classes: `.plan-field*`, `.plan-check`, `.plan__stack/row/list` where replaced): `.plan-grid[data-columns='2'|'4'|'7']` = `repeat(N, minmax(0, 1fr))`; `.plan-day[data-today='true']` 2 px `--color-accent` ring, no background; `.plan-meal[data-state='cooked'|'skipped']` opacity .55; `.plan-meal__recipe` `-webkit-line-clamp: 2`; `.plan-meal[data-unfilled]` dashed border. No `min-height`, no hex/rgb, no native control selectors.
- **Review round 2 (Designer)**:
  - **Unnamed `stock_coverage`** (the server never sends an Ingredient): `phraseWhy` still returns "uses what is in Stock" (kept for completeness), but `chips.whyChips` drops a `stock_coverage` why without `ingredient`, so it is in no chip list at all (`dayChip`, `heroChips`, `sheetChips`). A named one still shows "uses Stock: rice". Section 6 copy "uses what is in Stock" is therefore unreachable in chips by design.
  - **7 columns**: `groupByDay(slots, today, columns = 2)`; today spans 2 unless `columns === 7` (then 1, ring kept). `DayGroup.shortTitle` = Today / Tomorrow / Yesterday / short weekday ("Wed"). `DayTile` gains `compact?: boolean` (PlanScreen passes `columns === 7`) and shows `shortTitle` when compact. `DayTile` sets `data-dividers="true"` when the day has 3 or more slots.
  - **CSS contract**: `.plan-meal__head` does not wrap, `.plan-meal__actions` `flex: none`, `.plan-meal__slot` `min-width: 0` + ellipsis (Swap never drops under the label); no `overflow-wrap: anywhere` anywhere, Recipe name and chips use `overflow-wrap: break-word` + `hyphens: auto`; `.plan-day__title` wraps (break-word), never overflow hidden / ellipsis / nowrap; the meal divider is `[data-dividers] .plan-meal + .plan-meal { border-top: 1px solid ... }` only (no unconditional rule); `.plan-meal [data-kind]` has `justify-self: start`.
  - **StreakTile**: no visible heading (the metric label "zero-waste streak" says it); the section keeps `aria-label` "Zero-waste streak". Drop the `today__tile-title` h2.
  - **Regenerate copy** moves to `planStrings`: `regenerateConfirmTitle`, `regenerateConfirmLabel`, `regenerateNone`, `regenerateCount(n)`; `regenerate.ts` holds no literals.
  - Hero primary button (item 1): deferred to the WP3b primitive follow-up.
- check-ui: the Developer appends `web/src/features/plan web/src/features/today` to every rule's `fail_paths` in `scripts/check-ui.rules`.
