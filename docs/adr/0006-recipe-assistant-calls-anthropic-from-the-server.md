# The Recipe Assistant calls Anthropic from the server, with an Admin-held key encrypted under a required server secret, and only feeds Import Review

Status: **Accepted** (2026-11-10; amended the same day with plan v3: origin-bound key on every route, optional kept photo, Helm generates the secret by default). Design: [docs/dev/design/ai-recipe-import.md](../dev/design/ai-recipe-import.md).

Feeder gains an optional **Recipe Assistant**: a User gives a web page address, pasted recipe text or photos of a cookbook page or handwritten card, and a Claude model (Anthropic API) turns it into a Recipe File. It is off by default and is the first time Feeder sends household data to a third-party service, so these choices are recorded together:

1. **Server-side only.** The browser never calls Anthropic and never sees the API key. The Go server fetches pages (and photo URLs) through the same SSRF guard as Recipe File images, extracts the text and any schema.org Recipe data, prepares photos (decoded, shrunk, re-encoded without metadata; kept only if the User chooses one as the Recipe photo in Import Review, through the normal Recipe image path), calls the Messages API with the official Go SDK (`github.com/anthropics/anthropic-sdk-go`) and structured JSON output, and validates the result. The model always reads the source; schema.org data is only a hint, and there is no keyless import.
2. **The model's only product is a Recipe File, which goes through Import Review.** The model has no tools; its output is constrained to a projection of `recipe-file-v1.schema.json`, then re-validated against the full schema and the Recipe rules on the server. Nothing is saved without a User confirming Import Review. Fetched, pasted and photographed content is untrusted data in the prompt, so a prompt injection can at worst change the proposed Recipe, which the User sees before saving.
3. **One household-wide configuration, Admin-only** (spec §2): enable, API base URL, model and API key. Default model **Claude Haiku 5.5** (`claude-haiku-5-5`); the Admin may choose any model that supports structured output. Only the Anthropic Messages API with `x-api-key` is supported (directly or through a gateway that speaks it); not Bearer gateways, Bedrock, Vertex or Foundry. The key is write-only through the API (only "saved" and its last four characters are reported). An empty key field keeps the saved key; an explicit Remove clears it; **the saved key is bound to the saved origin (scheme, host, port)**: on every route that takes a base URL (save, models list, test connection) the saved key is used only when the origin is unchanged, otherwise a typed key is required; saving a new origin discards the saved key.
4. **The key is encrypted at rest** with AES-256-GCM under a subkey derived from **`FEEDER_SECRET_KEY`, which is required for the feature**. Feeder never creates a key file. Without the variable Feeder runs, but the Recipe Assistant cannot be turned on and Settings explains why; a malformed value stops start-up. The Helm chart supplies it from a Kubernetes Secret, never from a plain value: by default the chart generates one on install and keeps it across upgrades; an existing Secret overrides that. Rotating it means re-entering the API key.
   This is a deliberate exception to [ADR 0004](0004-go-binary-sqlite-on-data-volume.md), under which all state lives on the `/data` volume: the API key's ciphertext stays there, but the secret that decrypts it lives **outside** `/data` (environment or Kubernetes Secret), so a copy of the volume or of a backup does not reveal the API key.
5. **Every User may read recipes, within limits**: one running read per User (Admins included) and 30 reads per hour per Household for non-Admins; Admins are exempt from the hourly limit and their reads don't count toward it.
6. **No automatic fallback on a model refusal.** A refusal is shown as such, naming the model and suggesting another one; Feeder never silently retries on a different model.

**Considered options**
- *Browser calls the API directly with a per-User key*: no key storage on the server, but every User needs an Anthropic account, the key sits in the browser, and the page fetch hits CORS. Rejected.
- *Plain `net/http` instead of the SDK*: one less dependency, but we would re-implement typed errors, retry with `retry-after`, base URL handling, image blocks and Models API paging. The SDK is the documented default for Go. Accepted cost: a new module in `go.mod`.
- *Model output saved directly as Recipes*: faster, but it would bypass Ingredient matching, the unit check and the human check, and would let injected content write data. Rejected.
- *Key stored in plaintext in SQLite*: any copy of `feeder.db` or a backup leaks a billable credential. Rejected.
- *Auto-created key file `/data/secret.key`*: no setup, but anyone who can read the volume can decrypt the key, and the file travels with volume snapshots. Rejected by the user in favour of the required environment variable.
- *Keyless import of schema.org Recipe data*: free, but it can't produce Base Units, Unit Conversions, Shelf Life or Step kinds, and would flood Import Review. Rejected.
- *Anthropic's server-side refusal fallback*: would hide which model produced the Recipe and is unavailable for the default model (Haiku 5.5). Rejected.
- *Opus 5.5 as default*: best extraction short of Fable, but about 20–40 times the cost per read of Haiku 5.5. Rejected as default; offered in the picker.

**Consequences**
- Operators who want the Recipe Assistant must set `FEEDER_SECRET_KEY` (e.g. `openssl rand -base64 32`, or the chart's generated Secret, the default) and keep it outside `/data` and its backups. GitOps tools that render with `helm template` (e.g. Argo CD) can't keep a generated Secret and must use an existing one.
- Changing or losing `FEEDER_SECRET_KEY`, or restoring a backup on a server with a different one, leaves the API key unreadable; the Recipe Assistant stops until an Admin enters the API key again. There is no previous-key variable for rotation. Nothing else uses the secret key today.
- Haiku 5.5 as default keeps a read under one cent but may need more fixing in Import Review on messy pages and handwriting; the Admin can pick a stronger model.
- Photo reads need larger request bodies (up to 45 MiB); reverse proxies in front of Feeder must allow them (deploy guide).
- ADR 0002 keeps its meaning: no external product database is queried. The Recipe Assistant is opt-in, used only on an explicit User action, and never in the shop.
- Settings changes are recorded and shown to Admins only; a later decision may merge this change history with Access Request history into one Household activity log.
