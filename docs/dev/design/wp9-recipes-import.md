# WP9: Recipes + Import screens (round 2)

Spec: [ui-fix-plan.md](../../design/ui-fix-plan.md) 5.8 to 5.11, 2.8, 4.3, 4.4, 4.15, section 7 WP9; QA gaps G1, G2, B2 and the QA native-control inventory (wp4 note). Scope: `web/src/features/recipes/**`,
`web/src/features/import/**`, and the `fail_paths` lines of `scripts/check-ui.rules` (the designer already appended both folders to every rule, so the guards are red until the Developer finishes).
**No backend change** (`internal/recipe` untouched: the API already takes `memberId`, Step `uses` and `image`, and answers 422 `unknown_unit`). No new BDD: the Gherkin in `bdd/features/recipes/` already covers those endpoints.
Consumes WP3/WP4/WP5 primitives from `ui/` only. Hooks keep fetching; components only render (CLAUDE.md).

## Decisions
- **Recipes header** = `PageHeader` "Recipes" + primary sm `Button icon="add"` "New Recipe" + `IconButton icon="more" label="More actions"` opening `RecipesOverflowSheet`
  (a `BottomSheet` "More": `RecipeFileActions` as one `ListGroup` of three `ListRow`s Import / Export / Copy Agent Prompt, plus a "Show archived" row with a trailing `Switch`). The overflow is a sheet, not a popover menu, because there is no Menu primitive (see PRIMITIVE REQUESTS: none needed).
  `SearchField` "Search Recipes" (`useRecipes` gets `q` undefined when blank), then **one** `TagChips` group of `Chip kind="filter"` that scrolls horizontally with fade edges (CSS). Loading = `Skeleton`, error = `ErrorState` (retry refetches), empty = `EmptyState` with icon `recipes`.
- **Recipe tile** (`RecipeTile`): `Tile variant="media" stretched={{label: name, onActivate}}`, media = `RecipeThumb` (photo with `object-fit: cover`, or the generated Tag-icon tile; never a bare letter). Body: name (15/800, 2-line clamp, CSS) then a **separate meta row**: `Icon duration` + "45 min" (or "No Steps") and a `Chip kind="tag"`-less "+4 h ahead" `Chip kind="status"` with `advanceStep` icon; Ready Meal / Archived as `Chip kind="tag"`. Grid 2/3/4 columns via `BentoGrid`.
  `advanceWord` becomes "ahead" ("+4 h ahead"). `lib/tileArt.ts` and its test are deleted by the Developer (superseded by `RecipeThumb`/`tagIcon`).
- **Recipe detail**: `PageHeader` title = Recipe name (the only h1), leading back `IconButton`, actions `IconButton icon="edit" label="Edit"` and `IconButton icon="more" label="More actions"` (sheet rows Archive/Unarchive and Delete; the sheet closes before the dialog opens).
  Hero = `Tile variant="media"` with `RecipeThumb size="hero"` and the Ready Meal / Archived chips (the name stays in the header to keep one h1; the mockup's name-over-scrim is not done). Then `RecipeMetrics` (two `TileMetric` tiles: "4 portions per Batch"; "25 min cooking" with "+ 4 h ahead" beneath, so the Advance Step is no longer hidden), Ingredients tile
  (`IngredientLinesList` = a `dl` two-column grid: quantity | name + optional/note + Exclusion `IconButton icon="exclusion" pressed`), Steps tile (`StepsList`: `ol` rows with a 30 px soft number badge `[data-step-number]`, text, meta "Passive · 40 min" / "Advance Step · 4 h before" with `activeStep/passiveStep/advanceStep` icons, "Uses 2 clove garlic", Step photo through `RecipeThumb`), Advance Steps tile uses `variant="status" status="leftover"` is **dropped**: Advance Steps are shown in the Steps tile, flagged by their meta, so the leftover yellow is gone.
  Preferences tile: `MemberPicker` then `PreferenceToggles` (filter `Chip`s with `favourite/dislike/exclusion` icons; the plan says `Segmented`, but a state can be cleared by tapping it again and `Segmented` always has a value, so chips stay). Sticky `CookEntry` above the nav (`bottom: var(--nav-clearance)`).
- **G1 Member picker.** `useMemberPicker()` (members from settings' `useMembers`, the User from `app/useMe`) keeps the explicit pick in state; `memberId` (undefined until picked) feeds `useRecipePreferences(memberId)`, `selectedId` (`lib/memberPick.selectedMemberId`: pick, else the Member linked to the User, else null) is what the picker shows.
  `MemberSelect` is multi-valued, so `lib/memberPick.singleMember` turns its list into one id (the newly added one wins). No linked Member and no pick: hint "Choose a Member to set preferences for." and disabled toggles (the old "You are not linked" tile goes away because a Member can now be picked). No Members at all: the picker renders nothing.
- **G2 Cook / Batch (B2).** `CookEntry` = `Stepper` "Batches" (1 to `MAX_BATCHES` = 10, whole numbers; `lib/cookEntry`), hint "2 Batches · 8 portions" (`batchPortions`), primary "Start Cook Mode"; navigates to `cookPath(id, batches)` = `/cook/recipe/:id?batches=N` (read-only check of `features/cook/lib/scope.ts` and `CookScreen`: that is the route it expects; `batchesFrom` accepts any number above 0).
  The Batch count lives in the screen's state (default 1).
- **G2 Step image and `uses`.** `StepsEditor` takes `ingredients: IngredientRef[]` and `imageUpload` (the screen passes `usePhotoUpload`). Per Step: `TextArea` text, `Segmented` kind (Active, Passive, Advance Step; goes through `lib/steps.changeKind`), `NumberField` Duration or Lead time (unit "min"; the draft keeps strings), "After" as `Chip kind="filter"`s (`afterOptions`, `toggleAfter`),
  a Uses list (`lib/stepUses` add/update/remove; per use `IngredientSelect` "Ingredient used", quantity `TextField` "Quantity used" (text: fractions like "1 1/2" stay typeable, `draft.parseNumber` parses), `UnitSelect` "Unit used", remove `IconButton`), a `FileDrop accept="image/*"` Step photo with `RecipeThumb` preview and "Remove Step photo" (`setStepImage`). Reorder/remove are `IconButton`s (`moveUp`, `moveDown`, `delete`). No drag handle (no drag support in the primitives; arrows stay).
  `validateDraft` now checks each use (`steps.N.uses.M.ingredient|quantity|unit`, same codes as lines); `serverErrorKey` already maps the server paths.
- **G2 inline Unit Conversion.** The native unit `<select>` could not hold an unknown unit, which is why the prompt never showed. `UnitSelect` now offers "Use unit "handful"" (PRIMITIVE REQUEST 1), the row says "Feeder will ask how much 1 handful is when you save." (`lib/lineUnits.needsConversion`, instant) and Save runs the existing `parseUnknownUnit` flow in `useRecipeEditor` (works for lines and Step uses; `useRecipeEditor.uses.test` guards it).
  `UnitConversionPrompt` = `BottomSheet` + `NumberField` "Amount in g" + Save/Cancel (invalid = "Enter a number above 0."). `unitChoicesOf(ingredient)` feeds `UnitSelect`.
- **Editor layout.** Sections as tiles with headings Details, Photo, Ingredients, Steps (h2); sticky footer [Cancel tertiary] [Save Recipe primary]. `IngredientLineRow` = `IngredientSelect` (all Ingredients as options; `useIngredientSearch` and its server round trip are deleted), quantity `TextField`, `UnitSelect`, `Checkbox` "optional", note `TextField`, remove `IconButton`.
  `RecipeDetailsFields` = `TextField`/`TextArea`/`NumberField` (Yield; Cool-down and Leftover Use-by are nullable: cleared = '' = household default)/`Checkbox` (Ready Meal with description). `TagInput` becomes a `TextField` with Enter/comma commit. `PhotoPicker` = `FileDrop accept="image/*"` + `RecipeThumb` preview; a rejected file shows `photoErrors.unsupported`.
  Loading = `Skeleton`; saving errors inline (field errors on the fields, others in `ErrorState`).
- **Delete.** `useRecipeActions` (new hook) wraps `useConfirm().choose({ title: "Delete Roast tray?", body, tone: 'danger', confirmLabel: 'Delete', alternateLabel: 'Archive instead' })`: confirm deletes then navigates to /recipes, alternate archives, cancel does nothing, `already_planned` shows its message. `window.confirm` and `strings.deleteConfirm` are removed. `ConfirmProvider` is mounted by the shell (WP5) / `main.tsx`; the screen tests mount their own.
- **Import** (2.8): `ImportScreen` = `PageHeader` + three numbered step tiles (`Tile overline="Step n"`): (1) `AgentPromptStep` (Robot `agentPrompt` icon, help text, `CopyAgentPromptButton` as primary `Button icon="copy"`; copying announces through `useToast().show(message, { status })`, no `<p role=status>`), (2) `ImportSource` (`FileDrop accept=".json,application/json"`, a non-JSON drop shows `importStrings.rejectedFile`; `TextArea` "Or paste the JSON"; Review), (3) Review (the plan tiles once a plan exists; before that a muted "Review" placeholder tile).
  Review tiles migrate: `IngredientMatchTile` new-name input -> `TextField`, status `Chip kind="status"`, suggestions as filter chips (unchanged behaviour); `UnitPromptTile` -> `NumberField`; `RecipeConflictTile` buttons -> `Segmented` (Replace / Keep both / Skip is kept as buttons if the tests prefer: the existing tests only need button names); sticky `ConfirmTile` bar. `ExportPicker` = `ListGroup` of `ListRow`s (`leading` = `RecipeThumb size={40}`, `trailing` = `Checkbox` named after the Recipe) and an "All Recipes" `Switch` that selects all / clears (replaces the Select all / Clear buttons); download link keeps `exportSelected(n)` / `exportAll` ("Export all Recipes").
  `RecipeFileActions` is now the sheet's list (no pill links, no `.recipe-file-actions`).
- **CSS**: a new `features/recipes/recipes.css` and `features/import/import.css` (tokens only; `sizing`, `colour-literals`, `class-hooks` guards) replace any legacy class (`recipe-tile__*`, `recipe-photo`, `recipe-step-photo`, `recipe-file-actions`); delete what is unused. Every image is `max-width: 100%; object-fit: cover` (via `RecipeThumb`), nothing is wider than the viewport.
