# Sign-in needs a User's approval, not just a Google account

Feeder stays Google-only, but a Google account is no longer enough, and an Admin is no longer the only gate. Someone signs in straight away if their address was added to the Household (it is on the allowlist, or it is the email of a Member). Anyone else with a *verified* Google email creates an **Access Request** and waits on a page that shows nothing about the Household; they get no session and no data until **any signed-in User** approves it (one approval is enough; approving adds a non-Admin User, and the approver may link that User to one of the Members who has no User yet in the same step). A denial removes the request and the address may ask again after a cool-down. We considered keeping the Admin-only allowlist (rejected: a family member should be able to let in a relative without finding the Admin) and open sign-up (rejected: the Household's data, including names, schedules and photos, must stay private). Because strangers can now write to the database before they are trusted, requests are rate-limited per IP and per address, capped globally, expire after 14 days and are audited. This extends the access rules of spec §2; the allowlist remains the list of Users, and Admin-only powers (managing Members, Meal Slots, Shops, the allowlist and settings) are unchanged.

**Decisions after review.** (1) Both ways to be "added to the Household" stay: the allowlist and an optional **Member email** set by an Admin. A Member email never takes over a User: an address that already belongs to a User wins at sign-in, and an address may be used only once across Members, Users and the allowlist (case-insensitive); the Member editor and the allowlist both refuse a clash (`409 email_taken`). (2) Any User may approve, and may pick an unlinked Member while approving; the audit trail records the Member. Removing a User stays Admin-only. (3) `FEEDER_TRUST_PROXY` defaults to **false**: the rate limit uses the socket address, and an `X-Forwarded-For` header is believed only when the operator turns the setting on (the Helm chart does so when an ingress is enabled, because ADR 0004's reverse proxy is then in front). A direct-exposed instance can therefore not be talked past the per-IP limit by a forged header. (4) The Google photo is shown only from `googleusercontent.com`, and the UI falls back to initials when it fails to load.
