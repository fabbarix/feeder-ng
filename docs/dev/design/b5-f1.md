# B5-F1: a Meal Slot on one date, in the web (Plan, Today, board, Settings)

Team F1, beta.5. Test-first note by the designer / test author. Web only. Sources: [beta5-plan.md](beta5-plan.md) 2.1 and 2.2,
[beta5-reconcile.md](beta5-reconcile.md) 0.1, 1, 2, 9, 12 (F1 row), 13 (U1, U2, U3 = A), [ADR 0014](../../adr/0014-meal-slot-on-one-date.md),
the backend contract in `team/b5-sd` (`docs/dev/design/b5-sd.md`, section 3), GLOSSARY (**Not served**, **Guest**, **Attendance**, **Meal Slot**), the ux-brief (Bento).

Terms are the GLOSSARY's. "Who's eating", "Time today" and "Time on Thu" are labels, not terms.

## 1. What the User gets

For **any User** (not only the Admin), on Plan and Today, from today on:

| Choice | Where | Result |
|---|---|---|
| **Who's eating** | slot menu (every slot) | The Date Attendance sheet for that slot and date (Members, Courses, **Guests** 0 to 20); the date is read-only |
| **Not served** | slot menu, while no Course is Cooked or Not cooked (U2) | Confirm when Planned Meals go (from the dry run), a toast with Undo, then one compact row "Dinner · Not served" with **Plan Dinner again** |
| **Time today** / **Time on Thu** | slot menu | A dialog with the shared `TimeField`; **Back to 19:30** when the date has its own time; the block shows "20:15 · usually 19:30" |

Also: emptying Who's eating (no Member, no Guest) is Not served (U1); Guests eat every Course served and a Guests-only date is planned (U3, backend);
the pill suffix "+2 Guests"; offline the three choices are unavailable with "Needs a connection"; the read-only "Dates that differ" tile on
Settings > Meal Slots is filled; the Shopping List hint gets its **Mark it** button, which opens a slot's Mark as Cooked / Mark all Cooked sheet on the Plan.

## 2. Backend contract used (b5-sd, exactly)

| Call | Used for |
|---|---|
| `GET /api/meal-slots/{id}/dates/{date}` | `planApi.slotDate` (`SlotDateInfo`: `date, notServed, time\|null, usualTime, guests`) |
| `PATCH /api/meal-slots/{id}/dates/{date}` `{notServed?, time?: "HH:MM"\|null}` | `planApi.patchSlotDate`: Not served, Plan again (`notServed:false`), Time, Back to usual (`time:null`) |
| `PATCH ...?dryRun=1` `{notServed:true}` -> `{removes:{plannedMeals:[{courseId,courseName,recipeName,pinned,bought[]}]}}` | `planApi.notServedPreview`: the confirm list |
| `422 validation_failed` with `field` + `reason`: `date_past`, `slot_started`, `time_invalid`, `guests_invalid` | `slotDateErrorText` |
| `GET/PUT /api/meal-slots/{id}/attendance?date=` gains `guests`; `portionsNeeded` includes Guests; `DELETE` also resets Guests | `settingsApi.saveAttendance(..., guests)`, `DateAttendance.guests` |
| `GET /api/plan` slots gain `time` (effective), `usualTime`, `notServed`, `guests`; a Course's `unserved` may be `"not_served"` | `PlanSlot`, `Unserved`, board `SlotLike` |
| SSE `household {"changed":"slotDates"}` | plan refetch; "Dates that differ" refetch |

Reason `slot_started` is the contract's (b5-sd section 3; the plan's `slot_resolved` is not used).

## 3. Pure libraries (plain TypeScript, unit-tested)

**`plan/lib/slotDate.ts`**: `dateChoices(slot, today)` (which of Who's eating / Not served / Time / Plan again show), `isNotServed`,
`slotDayName` ("Thu Dinner"), `timeChoiceLabel` ("Time today" / "Time on Thu"), `choiceLabel` ("... · Needs a connection" offline),
`notServedConfirm(slot, preview)` + `needsNotServedConfirm`, `notServedToastText`, `notServedRowText`, `planAgainLabel`, `timeCaption`
("20:15 · usually 19:30"), `hasOwnTime`, `timeDialogCopy`, `canSaveTime`, `guestsSuffix` ("+2 Guests"), `attendeesLine` ("Anna, Sam + 2 Guests"),
`notServedToday`, `slotDateErrorText`.

Rules: all choices need a date of today or later; Who's eating and Time need a Course still to cook (or nothing planned yet); **Not served** also needs no
Course Cooked or Not cooked (U2) and a slot that is not already Not served; a Not served slot offers only **Plan Dinner again**.

**`plan/lib/courses.ts` `slotMenu(slot, today, dateChoices?)`**: with the third argument true the model also carries `whosEating`, `notServed`, `time`
(label), so a one-Course slot has a menu; without it nothing changes (every existing test stays green). `null` when no entry applies.

**`plan/lib/markSlot.ts`**: `markSlotPath` (`/plan?mark=<date>:<mealSlotId>`), `parseMarkSlotParam`, `markSlotTarget(slot)` (one Course to cook: that Course's
sheet; several: Mark all Cooked; none).

**`settings/lib/dateAttendance.ts`**: `clampGuests`, `portionsPreview(members, attendance, guests)`, `portionsPreviewText` ("6 portions of each Course"),
`emptiesDate`, `savingEmptiesDate(sent, current, usual)` (U1; a Courses-only save never empties), `guestsLabel`.

**`settings/lib/mealSlotCards.ts`**: `exceptionsFromPlan(planSlots)` (own time, Not served, Guests); `DatePart` gains `{kind:'guests'}`; `datesThatDiffer` orders
parts time, attendance, Guests, and Not served stays alone. **`settings/lib/dateCourses.ts`** `hasDateOverride` is also true for Guests (Reset drops them).

**`board/lib/tiles.ts`**: `notServedLine`, `tonightNotServed`; `tomorrowSlots` / `tomorrowLine` include a Not served slot.

**`shop/lib/lines.ts`**: `markItTarget(meals)` (oldest date, then Meal Slot id); `ListEntry.markIt`.

## 4. Hooks

- **`plan/hooks/useSlotDate.ts`** `useSlotDate(slots, today)` -> `SlotDateController`: `actions` (`SlotDateActions`: `offline`, `onWhosEating`, `onNotServed`, `onTime`,
  `onPlanAgain`) for the menu, tile and hero; `timeSlot`/`closeTime`/`saveTime`/`backToUsual`; `whosEating` (`target`, `close`, `beforeEmptying`, `onEmptied`).
  Not served: dry run, confirm only if Planned Meals go (`useConfirm`), PATCH, toast "Thu Dinner is not served" with Undo (`notServed:false`), refetch the plan.
  A refused call toasts `slotDateErrorText`. Offline: no request is made (`useConnectivity`).
- **`plan/hooks/useMarkSlotRoute.ts`**: reads `?mark=` on the Plan page, opens the slot's sheet through the screen's `useCookFlow` / `useAllCookedFlow` once the plan
  has loaded (once, not on a refetch), toasts "Nothing is left to mark Cooked there." and leaves for a slot with nothing to mark, and leaves when the sheet closes:
  back one step when the app was opened from elsewhere (the Shopping List), else `/plan` without the parameter. `usePlanScreen` calls it.
- **`settings/hooks/useAttendanceSheet.ts`**: Meal Slot + Members + the date's Attendance for a `WhosEatingTarget`; `save(attendance, courses, guests)` runs
  `beforeEmptying` when `savingEmptiesDate`, PUTs, then `onEmptied` (the Not served toast) instead of the "Attendance saved" toast, and closes; `reset`.
- **`settings/hooks/useDateExceptions.ts`**: reads `GET /api/plan` (key `['plan','dates-that-differ']`) and derives rows with `exceptionsFromPlan`.

Plan and Today never import Settings internals: they use `WhosEatingSheet` through `features/settings/index.ts`; the sheet takes the Not served confirm and toast as callbacks.

## 7. Decisions taken here (flagged, not in the docs)

1. **Mark it opens `/plan?mark=<date>:<mealSlotId>`**, a parameter of the Plan page, not a new route (a new route needs rows in `app/breadcrumbs` and `app/pageWidths`, which F1 does not own).
2. **"Dates that differ" reads `GET /api/plan`** (the Planning Horizon), because b5-sd has no list-of-dates route. It shows own time, Not served and Guests; a changed Attendance has no source and is not shown.
3. **Who's eating title** is "Who's eating <Slot> on <date>"; the date is read-only (reconcile Q5). Settings > Meal Slots keeps its editable date and the old title.
4. **Emptied date from Settings > Meal Slots** shows the note and saves with no confirm (the confirm and toast belong to Plan and Today, wired by callbacks).
5. **Cook captions** need no change: Cook Mode, the board and Today read the effective `time` / `at` the server sends.

## 9. Open questions for the product owner

1. **Emptying Who's eating on a started slot** (a Course Cooked or Not cooked): SD now refuses the attendance PUT with `409 {code: "slot_started"}`. The web stops the save and toasts Plan's `slotStarted` sentence reworded to "already Cooked or Not cooked" (Settings > Meal Slots and the Who's eating sheet via `settings/lib/errors.ts`; the Plan dry run keeps its `422 slot_started`).
2. **Time change on a past date** is refused by SD (`date_past`); the web offers no time choice on a past date.
3. **Undo of an emptied date** serves the date again (`notServed:false`); SD removes the empty override then, so the usual Attendance applies again (not the Members the User had before). Acceptable?
