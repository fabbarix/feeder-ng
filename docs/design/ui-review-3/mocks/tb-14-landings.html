Where each notification lands

internal/notify/compute.go and dispatcher.go set Payload.URL; web/src/features/notifications/sw/push.ts opens it.

NotificationLands on nowLands on after TB-14What the person sees
Advance Step due/plan/?step=<scope>:<step> TodayScrolls to Advance Steps and rings that row for 2 s; its Done is the next Tab stop. A step already done shows the toast "That Advance Step is already done."
Start cooking/plan/cook/meal/<date>/<slotId> Cook ModeOpens Cook Mode on Get ready (PC 6), or on the Step it was left at when that Cook Mode is already under way. A slot already Cooked lands on Today with the toast "Dinner is already marked Cooked."
Confirm Cooked/plan/plan?mark=<date>:<slotId> (exists, B5-F1)Opens Mark as Cooked (one Course) or Mark all Cooked (several) for that slot, the sheets the To confirm row opens; closing leaves the parameter. Nothing left: the existing toast "Nothing is left to mark Cooked there."
Leftover Use-by/plan/?leftover=<id> TodayOpens that Leftover's sheet (Had it, Threw it out, Freeze it). A Leftover already answered: toast "That Leftover is already answered."
Stock about to spoil/pantry/pantry?status=useSoon&lot=<id>The Pantry filtered to Use soon, with the Lot's sheet open (Use some, Throw out, Move).
Timer finished/board/cook/… of the timer's scopeMeal timer: /cook/meal/<date>/<slot>/<course> resumed at the timer's Step; Recipe timer: /cook/recipe/<id>. A window already showing that Cook Mode or the board is only focused. Free timer: /board.
Access Request/settings/access-requestsunchangedThe Sign-in requests page.

Which window: the service worker focuses a window already on the target path; otherwise it asks a window that is not in Cook Mode or on the board to navigate in-app (postMessage, no reload); otherwise it opens a new window. It never navigates a window that is in Cook Mode away from it.
